# Проверка всех текстов продукта

Задача: пройти **каждую строку, которую видит человек**, на **каждом из 15
языков**, и убедиться, что она написана на этом языке, а не переведена с
английского пословно. Плюс исправить то, что найдётся.

Это не проверка орфографии. Главный вопрос по каждой строке: **сказал бы так
живой человек на этом языке?** Если фраза грамматически верна, но звучит как
перевод инструкции - это дефект, и его надо исправить.

---

## 1. С чего начать

```
python tools/collect-copy.py
```

Соберёт всё в `docs/copy-review/`:

| Файл | Что внутри |
|---|---|
| `strings.json` | все строки: поверхность → язык → ключ → текст |
| `<язык>.md` | одна таблица на язык: ключ, английский оригинал, текущий перевод |
| `gaps.md` | ключи, которых в языке нет: читатель молча видит английский |

Скрипт только читает. После правок запусти его снова - увидишь, что изменилось.

Сейчас там **8720 строк на 15 языках**.

---

## 2. Где эти строки живут

Шесть мест, пять форматов. Править надо **в исходниках**, а не в
`docs/copy-review/` - те файлы генерируются.

| Поверхность | Файл | Формат | Языков |
|---|---|---|---|
| `site-home` | `cloud_api/src/home.ts` → `HOME_TEXT` | TS-объект, `key: 'текст'` | 14 |
| `site-link` | `cloud_api/src/index.ts` → `LINK_TEXT` | TS-объект, всё в одну строку на язык | 14 |
| `site-library` | `cloud_api/src/library.ts` → `SAY` | TS-объект | 14 |
| `extension` | `extension/_locales/<язык>/messages.json` | JSON, `{"ключ": {"message": "…"}}` | 15 |
| `app` | `mobile/lib/i18n.dart` → `_values` | Dart const map | 14 |
| `desktop` | `desktop_i18n.py` → `_TEXT` | Python dict, двойные кавычки | 14 |

Языки: `en ru et de fr es it pt pt_BR pl uk nl tr sv fi`
(`pt_BR` есть только в расширении.)

**Важно про ключи.** В `app` ключ - это сам английский текст, и в блоке `'en'`
лежат только четыре строки-исключения. Во всех остальных поверхностях ключ -
короткое имя, а английский вариант лежит в блоке `en`.

## 3. Правила, которые надо соблюсти

### 3.1 Название продукта не переводится

Везде **Subtitle Notes**, латиницей, во всех языках. Это уже чинили: русская
версия называла продукт «Примечания к субтитрам» и отправляла человека искать
в системном меню Android пункт, которого там нет - меню показывает `Subtitle
Notes`, потому что имя приложения не локализуется.

Проверить: ни в одной строке ни одного языка нет переведённого названия.

### 3.2 Пример - всегда чужой язык, переведённый на язык читателя

Пример существует ради одного: показать, что слово значит не то, что говорит
словарь. Показать это можно, **только если исходная строка на чужом языке**.

- Для 13 языков исходник - **английский**: `No one wants a record.`
  - словарь: «никто не хочет рекорд» / «keegi ei taha rekordit» / …
  - мы: «никому не нужна судимость» / «kellelgi pole vaja karistusregistri kannet» / …
- Для **английского** исходник - **французский**: `Il n'est pas dans son assiette.`
  - словарь: `He is not in his plate.`
  - мы: `He is not feeling well.`

Английская строка, «переведённая» на английский, не показывает ничего - это уже
было и это исправлено. Проверить, что нигде не вернулось.

Пример должен совпадать во всех четырёх местах, где он есть: сайт (`site-home`:
`line`, `mark`, `wrong`, `right`), расширение (`tourSubtitle`, `tourPick`,
`tourLine`, `tourMeaning`), приложение (`app`: `No one wants a record.`,
`record`, `No one wants a best-ever score.`, `No one wants a criminal record.`),
программа (`desktop`: `tour_line`, `tour_meaning`).

### 3.3 Дефис, а не длинное тире

Во всех текстах продукта только `-`. Ни `—`, ни `–`. Это уже приведено к
одному виду; проверить, что новые строки не принесли тире обратно.

Исключение: регулярные выражения в `extension/settings.js` и
`extension/background.js` - там тире значащие символы, они разбирают **чужие**
названия видео. Их не трогать.

### 3.4 Тон

- Обращение к человеку, а не описание системы.
  Плохо: «Ответ появится там, куда вы смотрите». Хорошо: «Ответ появится рядом».
- Без загадок в заголовках. Заголовок сайта - одно понятное утверждение:
  «Перевод по смыслу, а не по словарю».
- Без канцелярита и без маркетингового пафоса.
- Числа и интервалы называть прямо: «Сначала через день, потом через три,
  потом через неделю», а не «повторение с растущими интервалами».

### 3.5 Что должно быть верно фактически

Строка не должна обещать того, чего нет, и не должна описывать чужой жест:

- В **приложении на телефоне** нет клавиатуры: нельзя писать «зажмите клавишу»
  как инструкцию для телефона. Способ на телефоне - выделить текст и выбрать
  `Subtitle Notes` в меню.
- В **расширении** жест - зажатая клавиша и протяжка по субтитру.
- В **программе** - `Ctrl+Alt+S` и субтитры в VLC.
- Расширение **уже в Chrome Web Store**. Приложение для Android ставится
  файлом. Установщик Windows не подписан. Тексты не должны утверждать иного.

## 4. Что именно проверять по каждой строке

Для каждой строки в `<язык>.md`:

1. **Естественность.** Читается как написанное на этом языке?
2. **Смысл.** Совпадает с английским по сути, а не по словам?
3. **Длина.** Не длиннее английского в полтора раза без причины - в интерфейсе
   есть узкие места (кнопки, чипы, карточки).
4. **Согласованность терминов.** Один и тот же предмет называется одинаково во
   всех шести поверхностях. Смотри глоссарий ниже.
5. **Плейсхолдеры.** Если в строке есть `$count`, `${stats.unlocked}`, `{path}`,
   `{version}` и подобное - они должны остаться **буква в букву**.
6. **Правила из раздела 3.**

### Глоссарий: одно понятие - одно слово

| Понятие | en | ru | Комментарий |
|---|---|---|---|
| collection of saved words | library | библиотека | не «коллекция», не «словарь» |
| the saved unit | card | карточка | |
| the line a word came from | line / sentence | фраза / строка | внутри одной поверхности - одинаково |
| spaced repetition | revision | повторение | не «ревизия» |
| the browser part | extension | расширение | |
| the Windows part | program | программа | не «приложение» |
| the phone part | app | приложение | не «программа» |
| sign in | sign in | войти | не «авторизоваться» |

Если в глоссарии чего-то не хватает - допиши сюда, это часть работы.

## 5. Пробелы в переводах

`docs/copy-review/gaps.md` перечисляет ключи, которых в языке нет. Такой ключ
не ломает сборку - человек просто молча видит английскую строку посреди своего
языка. Их надо дописать.

На момент составления: в `app` не хватает от 1 до 6 ключей в 11 языках
(`Connect your phone`, `Settings`, `Sources`, `System language`, `As in the
file`, `Auto`). В остальных поверхностях пробелов нет.

## 6. Как править, чтобы ничего не сломать

- **`extension/_locales/*.json`** - UTF-8, отступ 2 пробела, файл кончается
  переводом строки. Не менять порядок ключей и не трогать `description`.
- **`mobile/lib/i18n.dart`** - Dart const map. Внутри строки: `\'` для
  апострофа и **`\$` для доллара** (иначе Dart попробует подставить
  переменную). Два одинаковых ключа в одном языке - **ошибка компиляции**,
  а не предупреждение.
- **`cloud_api/src/*.ts`** - одинарные кавычки, апостроф экранируется `\'`.
- **`desktop_i18n.py`** - двойные кавычки, апостроф не экранируется.
- Не менять переводы строк в файле целиком: часть файлов в репозитории с CRLF.
  Правь строку, а не переписывай файл.

## 7. Проверки, которые обязаны проходить после правок

```
node extension/check-locales.mjs          # каждая строка расширения в 15 языках, без дыр
node extension/check-episode-parsing.mjs  # разбор сезона и серии
node extension/check-answer.mjs           # какой из двух ответов показывает карточка
node cloud_api/scripts/check.mjs https://app.subtitlenotes.workers.dev
cd mobile && flutter analyze --no-pub lib/     # ловит дубли ключей в i18n.dart
python test_overlay_logic.py
python tools/collect-copy.py              # пересобрать выгрузку
```

Сайт не пересобирается сам: после правок в `cloud_api/src/` нужен
`cd cloud_api && npx wrangler deploy`.

## 8. Что прислать в отчёте

По каждой найденной проблеме:

1. поверхность и ключ (`site-home` / `h1`), язык;
2. что там сейчас;
3. что должно быть;
4. почему - одной строкой (не по-русски / противоречит другому месту / обещает
   то, чего нет / плейсхолдер потерян).

Отдельным списком - **строки, которые ты изменил**, и результат прогона
проверок из раздела 7.

Если по какому-то языку уверенности нет - так и написать, а не переписывать
наугад. Ошибочная правка в языке, которого никто в команде не читает, хуже
неудачной формулировки.
